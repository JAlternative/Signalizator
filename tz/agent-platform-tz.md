# Техническое задание
## Проект: Agent Platform

### 1. Назначение проекта
Agent Platform — личная Java-платформа агентов-наблюдателей для поиска полезных сигналов и возможностей дохода.

Проект создается с двумя целями:
1. Максимально прокачаться по темам Яндекс Практикума на реальном приложении.
2. Получить личный инструмент, который помогает находить сигналы и принимать решения самостоятельно.

Проект не предназначен для продажи подписки, SaaS-модели или работы на внешних пользователей.
Это личная система поддержки решений.

### 2. Общая концепция
Система строится как модульная платформа агентов.

Есть общее ядро платформы, которое отвечает за:
- запуск агентов
- сбор данных
- нормализацию данных
- хранение истории
- rules engine
- signal engine
- уведомления
- аудит
- REST API
- безопасность
- UI на Jmix

На это ядро подключаются отдельные агенты.
Первый агент — FinSignal.

В будущем могут быть добавлены:
- агент по ставкам
- агент по купонам и акциям
- агент по объявлениям
- другие агенты, использующие ту же платформу

### 3. Первый модуль: FinSignal
FinSignal — агент для мониторинга акций и рыночных сигналов.

#### 3.1. Основной источник данных MVP
Подтвержденный основной источник данных для первой версии:
- MOEX ISS

#### 3.2. Что делает агент FinSignal
Агент:
- получает данные по выбранному watchlist инструментов
- сохраняет рыночные снапшоты
- рассчитывает rule-based сигналы
- формирует объяснение сигнала
- показывает сигнал в UI
- не совершает автопокупку и не создает автозаявки

#### 3.3. Что агент анализирует
В MVP агент анализирует:
- текущую цену
- bid / offer
- VWAP
- объем
- количество сделок
- торговый статус
- историю котировок по инструменту

### 4. Ограничения проекта
В первой версии запрещено:
- автоторговля
- автоматическая отправка заявок брокеру
- полная автоматизация инвестиционного решения
- многопользовательский режим
- перепродавать сервис другим пользователям

Система только подсказывает сигналы и объясняет, почему они появились.
Финальное решение всегда принимает пользователь вручную.

### 6. MVP: функциональные требования
В первой версии обязательно должно быть реализовано:

#### 6.1. Платформа агентов
- возможность зарегистрировать агент
- возможность запускать агента по расписанию
- единый формат хранения сигналов
- единый формат хранения снапшотов
- аудит событий платформы

#### 6.2. Работа с инструментами
- список инструментов
- watchlist пользователя
- просмотр инструмента
- история ценовых точек по инструменту

#### 6.3. Сигналы FinSignal
В MVP реализуются 4 сигнала:
1. Аномальная дневная просадка
2. Отклонение от VWAP
3. Расширение спреда как анти-сигнал
4. Изменение trading status

#### 6.4. Сигналы должны содержать
Каждый сигнал должен содержать:
- идентификатор
- время возникновения
- источник
- инструмент
- тип сигнала
- важность
- краткий заголовок
- объяснение
- фактические данные, на основе которых он сработал
- статус сигнала
- dedup key

#### 6.5. Управление правилами
- просмотр списка правил
- включение и выключение правила
- редактирование параметров правила
- версия правила
- история изменения правила

#### 6.6. История и бумажные позиции
- история сигналов
- подтверждение сигнала
- отключение сигнала на время
- paper positions без реальной торговли

#### 6.7. Безопасность
- один пользователь
- JWT authentication
- закрытый доступ к системе
- аудит действий пользователя

### 7. Нефункциональные требования
- проект должен быть модульным
- проект должен расширяться новыми агентами без переписывания ядра
- все важные настройки должны быть вынесены в конфигурацию
- должна быть история сигналов и данных
- должна быть возможность воспроизвести срабатывание сигнала
- логи должны быть структурированными
- должны быть health-check и metrics
- проект должен быть готов к контейнеризации

4. Экран редактирования правила

- ядро платформы
- backend API
- Jmix UI

### 13. Правила принятия решений в проекте
- сначала строится стабильное ядро платформы
- потом полностью доводится один агент
- потом добавляются новые агенты
- архитектура важнее количества фич
- сигналы должны быть объяснимыми
- новые модули не должны ломать core

### 14. Итоговый образ проекта
На выходе должен получиться не учебный CRUD, а взрослая модульная backend-платформа на Java:
- с ядром агентов
- с первым рабочим модулем FinSignal
- с Jmix UI
- с историей сигналов
- с правилами
- с расширяемой архитектурой
- с заделом под новые источники и новые агенты
